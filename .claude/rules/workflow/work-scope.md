# 작업 범위

## 커밋

- 하나의 커밋은 하나의 목적을 가진다. 커밋 type 하나로 설명되지 않으면 나눈다
- 상한 200줄(추가+삭제), 파일 8개
- 착수 전에 예상 변경 크기(파일 수·줄 수)를 보고한다. 상한을 넘으면 시작하지 않고 단위별 내용과 순서를 적은 분할 계획을 먼저 낸다
- 작업 중 변경이 착수 전 보고한 예상을 넘게 되면 그 자리에서 멈춘다. 예상치를 벗어난 이유와 조정된 범위를 보고한 뒤 진행한다
- 서식만 바뀐 것(`style`)과 이름만 바뀐 것(`refactor`)은 기능 변경과 섞지 않는다

## PR

- 목표 400줄, 상한 600줄(`origin/main` 대비 추가+삭제)
- 목표를 넘으면 나눌 수 있는지 먼저 보고, 상한은 넘지 않는다

## 집계 제외

- `pnpm-lock.yaml`
- 이미지 같은 바이너리는 줄 수만 제외. 파일 수에는 포함

## 예외

큰 파일 하나를 지우는 것처럼 나눌 수 없는 변경은 그 커밋·푸시에만 `LEFTHOOK_EXCLUDE=work-scope`를 붙인다. `--no-verify`는 쓰지 않는다.

## 규칙과 강제

| 규칙                                     | 강제                                                                                                                          |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 커밋 200줄·8개 파일 이하                 | `.lefthook/check-work-scope.sh commit`, lefthook `pre-commit`. `--amend`·rebase로 커진 커밋은 `pre-push`가 커밋별로 다시 잰다 |
| 작업 중 변경이 예상을 넘으면 멈추고 보고 | 없음. 사람이 지킨다                                                                                                           |
| PR 600줄 이하. 400줄 넘으면 경고         | `.lefthook/check-work-scope.sh push`, lefthook `pre-push`                                                                     |
| 한 커밋 한 목적                          | 없음. `commit` 스킬이 나눈다                                                                                                  |

상한 값과 집계 제외 경로를 바꿀 때는 `.lefthook/check-work-scope.sh` 맨 위와 이 문서를 같은 커밋에서 고친다.
