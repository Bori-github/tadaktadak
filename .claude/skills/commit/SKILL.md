# 커밋

## 형식

```
<type>: <한국어 설명>

[본문]
```

제목은 명사형으로 종결한다.
제목을 소문자 영문으로 시작하지 않는다.

| type       | 쓰는 곳                                  |
| ---------- | ---------------------------------------- |
| `feat`     | 새 기능                                  |
| `fix`      | 버그 수정                                |
| `refactor` | 동작이 그대로인 정리                     |
| `docs`     | 문서                                     |
| `test`     | 테스트                                   |
| `chore`    | 설정, 의존성                             |
| `build`    | 빌드와 배포 설정                         |
| `ci`       | CI 설정                                  |
| `perf`     | 성능 개선                                |
| `style`    | 서식만 바뀐 것. Prettier가 하므로 드물다 |
| `revert`   | 이전 커밋 되돌리기                       |

## 본문

- diff를 요약하지 않는다. diff를 봐서는 알 수 없는 판단 근거만 쓴다
- 생략할 수 있다
- 생성 도구 서명(`Co-Authored-By`)은 요구받을 때만 붙인다

## 순서

1. `git status --short`와 `git diff`로 변경 사항을 읽는다
2. 최소한의 논리적인 단위로 커밋을 나눈다. 한 커밋 200줄을 넘으면 `git add -p`로 더 나눈다 (`.claude/rules/workflow/work-scope.md`)
3. 커밋 메시지 초안을 보여 주고 **멈춘다**
4. 사용자가 지시하면 그때 `git add`와 `git commit`을 실행한다

**초안만 보여 주고 커밋하지 않는다.** 훅 동작을 확인하려는 경우에도 마찬가지다. 확인이 필요하면 `pnpm exec lefthook run pre-commit`으로 커밋 없이 돌린다.
