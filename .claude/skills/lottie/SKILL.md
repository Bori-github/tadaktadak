# Lottie 규칙

스플래시와 루트 에러 화면은 테마마다 Lottie를 하나씩 사용하며, 화면 코드는 모든 테마의 Lottie를 같은 방식으로 배치한다. 아래 규칙을 지키면 Lottie를 추가하거나 교체해도 코드 수정 없이 모든 테마에서 같은 배치로 표시된다.

- 규칙마다 앱의 동작과 위반 시 결과를 함께 적는다
- 수치는 코드 상수 이름이나 Lottie 필드로 적는다. 현재 값은 해당 코드와 파일에서 확인한다
- 규칙을 바꾸면 해당 코드도 같은 작업에서 수정한다

## 1. 공통

### 파일

- 경로
  - 스플래시: `assets/lottie/splash-<테마 ID>.json`
  - 에러 화면: `assets/lottie/error-<테마 ID>.json`
  - 테마 ID: `src/entities/theme/config/themes.ts`의 `THEME_IDS`
- 테마 추가 시 함께 수정
  - `src/app/ui/splash/Splash.tsx`의 `SPLASH_ANIMATIONS`
  - `src/app/ui/root-error-screen/RootErrorScreen.tsx`의 `ERROR_ANIMATIONS`
  - 누락 시 `Record<ThemeId, …>` 타입 검사 실패
- 두 화면은 표시 중인 테마의 Lottie만 `require`로 로드
- `assets/lottie/`는 `.prettierignore` 대상. 한 줄 JSON 유지

### 캔버스

- 모든 Lottie의 `w`, `h`를 기존 Lottie와 같은 값으로 통일
  - 이유: 두 화면이 캔버스를 화면 가운데에 배치하므로, 캔버스 크기가 다르면 테마마다 그림 위치가 달라짐
- 화면 높이가 `h`보다 낮으면 캔버스 위아래가 같은 높이로 잘림 → 그림은 캔버스 세로 가운데(`h / 2`) 근처에 배치

### 재생 시간

- 재생 시간 = `op / fr`초. 코드가 Lottie 값에서 계산하므로 길이 변경 시 코드 수정 불필요
- `fr`은 기존 Lottie와 같은 값으로 통일
- 스플래시 길이는 앱 시작 시간에 그대로 더해짐 → 기존 스플래시보다 길게 만들 때는 사용자와 먼저 결정

### 도트

- 2px 정사각형 도트로 그림
- 도트 좌표는 2px 단위

## 2. 스플래시

### 앱 동작

1. OS가 네이티브 스플래시 표시. 배경색과 로고 크기는 `assets/bootsplash/manifest.json`, 로고 이미지는 `assets/bootsplash/logo.png`. JS 실행 전이라 테마 구분 불가
2. 테마 복원 후 `Splash` 마운트, 같은 로고 이미지 표시
3. 재생 시작 시 로고 이미지 숨김(`logoOpacity.value = 0`), Lottie 0프레임부터 렌더링
4. 1회 재생. 마지막 `FADE_MS` 동안 전체 페이드아웃 후 타이머 화면 표시
5. Lottie 캔버스는 네이티브 로고와 같은 비율로 스케일(`logoScale`)

### 규칙

- **0프레임 = 네이티브 로고**
  - 이유: 로고 이미지를 숨기는 프레임에 Lottie 0프레임이 같은 자리를 이어받음
  - 위반 시: 재생 시작 프레임에 로고가 다른 그림으로 바뀜
  - 로고 도트 출처: `assets/lottie/splash-campfire.json` 0프레임의 `logs`, `match` 레이어. 새 스플래시는 이 두 레이어의 도트를 같은 좌표/색으로 0프레임에 배치
  - 네이티브 로고(`assets/bootsplash/logo.png`)를 바꾸면 모든 스플래시 Lottie의 0프레임을 함께 수정
- **배경색 레이어 없음**
  - 이유: 캔버스가 로고 비율로 스케일되어 화면 전체를 덮지 못함
  - 위반 시: 캔버스 크기의 사각형만 다른 색으로 표시
  - 스플래시 배경은 `assets/bootsplash/manifest.json`의 `background` 유지
- **1회 재생 기준으로 구성**
  - 마지막 프레임에서 정지한 채 페이드아웃 → 마지막 `FADE_MS` 구간에 핵심 장면 배치 금지

## 3. 에러 화면

### 앱 동작

- 렌더링 에러 시 `RootErrorScreen`이 Lottie 캔버스 크기(`w`×`h`)의 무대를 화면 가운데에 배치하고 Lottie 무한 반복
- 무대 안에 문구와 「다시 시작」 버튼을 가로 가운데로 배치
- 세로 위치 계산
  - 그림 하단: `src/app/lib/lottieDotBottom.ts`의 `getLottieDotBottom` 결과(모든 키프레임 중 가장 아래 사각형 도트의 하단 y)
  - 문구 상단 = 그림 하단 + `MESSAGE_GAP`
  - 버튼 상단 = 문구 상단 + `BUTTON_OFFSET`
  - 계산 불가(`null`) 시 그림 하단 = 무대 세로 가운데(`h / 2`)
- 그림 크기와 관계없이 문구는 항상 그림 하단에서 `MESSAGE_GAP` 아래에 배치 → 테마마다 그림 높이가 달라도 같은 간격

### `getLottieDotBottom` 계산 대상

- 레이어 위치 `ks.p.k`: 정지 값 `[x, y, 0]` 또는 키프레임 배열의 각 `s`
- 레이어 도형 중 `ty: "rc"`(사각형)의 위치 `p.k`, 크기 `s.k`. 그룹(`gr`) 내부 포함
- 사각형 하단 = 레이어 위치 y 최댓값 + 사각형 위치 y 최댓값 + 사각형 높이 최댓값 / 2
- 위 세 값 외의 변환은 계산에서 제외 → 아래 규칙 적용

### 규칙

- **그림 도트는 사각형(`rc`)**
  - 타원(`el`), 패스(`sh`), 그라디언트(`gf`)는 계산 제외 → 빛 번짐처럼 그림 하단에 포함하지 않을 연출에만 사용
  - 위반 시: 그림 하단 계산 불가 → 문구가 무대 세로 가운데 기준으로 배치되어 그림과 겹칠 수 있음
- **도트 레이어 변환은 위치만 사용**
  - 레이어 `ks`의 `s`(스케일), `r`(회전), `a`(기준점)는 기본값 `[100, 100, 100]`, `0`, `[0, 0, 0]`
  - `parent` 미사용, 그룹 변환(`tr`) 기본값
  - 위반 시: 실제 렌더링 위치와 계산 위치가 달라 문구가 그림과 겹침
- **위치 분리(`s: true`) 미사용**
  - After Effects 「Separate Dimensions」 출력은 `{ "s": true, "x": …, "y": … }` 형식이고 `k`가 없음
  - 위반 시: 해당 레이어가 계산에서 제외
- **움직이는 도트는 홀드 키프레임(`"h": 1`)**
  - 계산은 키프레임 값만 사용
  - 위반 시: 키프레임 사이 보간 곡선이 더 아래로 내려가는 구간을 계산에서 놓침
- **비표시 구간의 도트도 그림 영역 안에 유지**
  - 투명도 0 구간, 레이어 표시 범위(`ip`~`op`) 밖의 위치도 계산에 포함
  - 위반 시: 그림 하단이 실제보다 아래로 계산되어 문구가 그림에서 떨어짐
- **버튼이 무대 안에 들어오도록 그림 하단 제한**
  - 그림 하단 + `MESSAGE_GAP` + `BUTTON_OFFSET` + 버튼 높이(`BUTTON_HEIGHT_IN_DOTS` × `BUTTON_DOT_SIZE`) ≤ `h`

### 도트 레이어 예시

```json
{
  "ty": 4,
  "nm": "snowman",
  "ks": { "o": { "a": 0, "k": 100 }, "r": { "a": 0, "k": 0 }, "p": { "a": 0, "k": [0, 0, 0] }, "a": { "a": 0, "k": [0, 0, 0] }, "s": { "a": 0, "k": [100, 100, 100] } },
  "shapes": [
    {
      "ty": "gr",
      "it": [
        { "ty": "rc", "p": { "a": 0, "k": [196, 447] }, "s": { "a": 0, "k": [26, 2] }, "r": { "a": 0, "k": 0 } },
        { "ty": "fl", "c": { "a": 0, "k": [0.875, 0.91, 0.961, 1] }, "o": { "a": 0, "k": 100 } },
        { "ty": "tr", "p": { "a": 0, "k": [0, 0] }, "a": { "a": 0, "k": [0, 0] }, "s": { "a": 0, "k": [100, 100] }, "r": { "a": 0, "k": 0 }, "o": { "a": 0, "k": 100 } }
      ]
    }
  ],
  "ip": 0,
  "op": 173
}
```

- 사각형 `p`는 중심 좌표. 예시는 x 183~209, y 446~448의 가로 13도트 줄, 그림 하단 448
- 같은 색 도트를 그룹 하나로 묶고 가로로 연속된 도트를 사각형 하나로 병합 → 파일 크기 감소
- 움직이는 도트 위치 키프레임: `"p": { "a": 1, "k": [{ "t": 0, "s": [0, 0, 0], "h": 1 }, { "t": 6, "s": [0, 2, 0], "h": 1 }] }`

### 그림 하단 확인

- 모든 `assets/lottie/error-*.json`에 `getLottieDotBottom` 실행
- `null` = 계산 대상 사각형 도트 없음
- 결과와 실제 그림의 최하단 도트 하단이 다르면 위 규칙 위반

## 4. 적용 순서

1. 위 규칙으로 스플래시/에러 화면 Lottie 작성
2. `assets/lottie/splash-<테마 ID>.json`, `assets/lottie/error-<테마 ID>.json`으로 저장
3. 새 테마면 `SPLASH_ANIMATIONS`, `ERROR_ANIMATIONS`에 항목 추가
4. 에러 화면 Lottie 그림 하단 확인
5. `pnpm check`, `pnpm test` 실행
6. 실기기 확인
   - 스플래시: 앱에서 대상 테마 선택 → 앱 종료 후 다시 진입 → 네이티브 로고에서 Lottie로 끊김 없이 전환되는지 확인
   - 에러 화면: 개발 빌드의 개발 패널 「에러」 버튼 → LogBox 「Dismiss」 → 문구/버튼이 그림 바로 아래에 겹치지 않는지 확인
