# 테스트 주도 개발

```
실패하는 테스트 없이 프로덕션 코드를 작성하지 않는다
```

테스트보다 먼저 작성한 프로덕션 코드는 삭제하고 테스트부터 다시 작성한다. 참고용으로 보존하지 않는다.

## 사이클

동작 단위로 RED → GREEN → REFACTOR 사이클을 반복한다.

### RED: 실패하는 테스트 작성

1. 테스트 본문을 작성하기 전에 **프로덕션 코드가 어떻게 바뀌면 이 테스트가 실패하는지** 한 줄로 명시한다. 명시하지 못하면 테스트를 작성하지 않는다
2. 동작 하나만 검증하는 테스트를 작성한다
3. `pnpm test <테스트 파일>`을 실행해 실패를 확인한다
4. 실패 원인을 판정한다

| 결과                                                       | 판정                                                                                           |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 단언 실패(기대값 불일치)                                   | RED. GREEN 단계로 진행한다                                                                     |
| `Cannot find module`, `is not a function`, 오타, 문법 오류 | RED가 아니다. 오류를 수정하고 다시 실행한다. 새 함수는 시그니처만 있는 빈 구현을 먼저 추가한다 |
| 통과                                                       | 기존 동작을 검증하는 테스트다. 테스트를 수정한다                                               |

### GREEN: 최소 구현

1. 테스트를 통과시키는 최소한의 코드를 작성한다. 테스트가 요구하지 않는 옵션과 분기는 추가하지 않는다
2. `pnpm test <테스트 파일>`을 실행해 통과를 확인한다
3. `pnpm test`로 전체 테스트를 실행한다. 이번 변경과 무관한 실패도 테스트 이름과 함께 보고한다

테스트가 실패하면 테스트가 아니라 프로덕션 코드를 수정한다.

### REFACTOR: 리팩터링

GREEN 이후에만 진행한다. 중복 제거, 이름 변경, 함수 추출로 범위를 한정하고 동작은 추가하지 않는다. 리팩터링 후 `pnpm test`가 통과해야 한다.

## 버그 수정

버그를 재현하는 실패 테스트를 먼저 작성하고 같은 사이클을 따른다.

## 테스트 작성

### 실제 동작을 단언한다

- 대상 모듈이 export하는 함수와 컴포넌트로 검증한다. 내부 구현을 바꿔도 동작이 같으면 테스트가 통과해야 한다
- 기대값은 리터럴로 작성한다. 테스트 대상 함수나 그 헬퍼로 기대값을 계산하면 테스트가 항상 통과한다
- 목(mock)의 존재가 아니라 실제 컴포넌트의 결과를 단언한다
- 목으로 대체하기 전에 실제 메서드의 부작용을 확인한다. 실행이 느리거나 외부 의존성을 호출하는 계층만 목으로 대체하고, 테스트가 의존하는 부작용은 실제 구현으로 둔다
- 목의 응답은 실제 응답 구조의 필드를 모두 포함한다
- 테스트에서만 호출하는 정리 함수는 프로덕션 코드가 아니라 테스트 파일에 정의한다

### 저장소 테스트 규칙

- 대상 함수나 컴포넌트를 가리키는 `describe` 제목은 대상의 JSDoc 첫 문장으로 작성한다. 대상에 JSDoc이 없으면 JSDoc을 먼저 작성한다
- 한 대상의 테스트를 장면별로 묶은 `describe` 제목은 장면 이름으로 작성한다
- `it` 제목은 검증하는 동작을 `.claude/docs/terms.md`의 용어로 작성한다. prop과 함수 이름 같은 코드 식별자와 식별자에 붙은 반환값·prop 값은 쓸 수 있고, 지시어와 내부 값(리터럴, 색 코드, 모드·방향 값)은 제목에 포함하지 않는다
- `it.each` 행은 사람이 읽는 이름 열(`label`, `situation` 등)을 둔 객체로 작성하고 제목에서 `$열이름`으로 참조한다
- 피그마에서 옮긴 상수의 길이, 문자, 값만 검증하는 테스트는 작성하지 않는다. 그 상수에 의존하는 동작을 테스트한다

## 예외

테스트로 결과를 검증할 수 없는 변경은 착수 전에 사용자 승인을 받는다. 승인 없이 사이클을 생략하지 않는다.

## 완료 조건

- [ ] 새 함수마다 테스트가 있다
- [ ] 구현 전에 테스트마다 단언 실패를 확인했다
- [ ] 테스트마다 프로덕션 코드가 어떻게 바뀌면 그 테스트가 실패하는지 명시할 수 있다
- [ ] 상수 값 변경, 분기 반전, 빈 값 반환으로 프로덕션 코드를 변형하면 테스트가 하나 이상 실패한다
- [ ] `pnpm test` 전체가 통과하고, 이번 변경으로 새로 생긴 경고와 오류가 없다

하나라도 충족하지 못하면 사이클을 생략한 것이다. 충족하지 못한 동작의 RED 단계부터 다시 진행한다.
