# 작업 시작

`.claude/rules/workflow/task-tracking.md`의 작업 시작 순서를 실행한다. 단계, 생략 조건, 데이터 소스 ID는 그 문서를 따른다.

## 절차

1. **작업 유형 결정** — 요청에서 WBS 작업 유형(기능, 문서, 개발 환경, 이슈)과 브랜치 type을 정하고, 기능 명세와 테스트 케이스 단계의 진행 여부와 함께 사용자에게 확인한다
2. **템플릿 확인** — Notion 행을 만들기 직전에 대상 데이터 소스를 fetch해 `page_templates`를 확인한다. WBS 행은 작업 유형에 맞는 템플릿(`FE(기능)`, `FE(문서)`, `FE(개발 환경)`, `FE(이슈)`)으로 만든다
3. **단계별 승인** — 기능 명세, 테스트 케이스, WBS 행은 초안을 대화에 보여 주고 승인받은 뒤 생성한다. 한 단계의 승인으로 다음 단계를 진행하지 않는다
4. **WBS 행 속성** — 업무 영역, 작업 유형, 우선순위, 작업일정(오늘)을 입력한다. 우선순위는 데이터 소스의 `우선순위` 설명을 기준으로 정하고, 진행현황은 기본값으로 둔다
5. **TASK ID 확인** — 생성한 행을 다시 조회해 TASK ID를 확인한다
6. **브랜치 생성** — 작업 위치(현재 폴더에서 전환, 새 워크트리)를 사용자에게 묻고 `git switch --no-track -c <브랜치> origin/main`으로 만든다. upstream이 `origin/main`으로 잡히면 push가 main으로 갈 수 있으므로 `--no-track`을 사용한다

완료 기준: TASK ID가 있는 WBS 행과 그 번호로 시작하는 브랜치가 있고, 작업 위치가 그 브랜치로 전환된 상태
